# 04 - 技能系统

> AI 如何通过技能（Skills）扩展能力

## 概览

技能是 Hermes 的**过程性记忆** — 它让 Agent 能够学习新的能力，并在后续对话中自动使用。

```
用户: "帮我生成一个 Python 数据分析脚本"
Agent: 搜索已安装技能 → 找到 "python-data-analysis" 技能 → 按照技能指令执行
```

## 技能的三层结构

### 1. 捆绑技能（Bundled Skills）
随 Hermes 安装一起提供，存储在 `skills/` 目录：

```
skills/
├── research/
│   ├── arxiv/
│   │   └── SKILL.md
│   └── web-research/
│       └── SKILL.md
├── productivity/
│   ├── git-workflow/
│   │   └── SKILL.md
│   └── ocr-and-documents/
│       ├── SKILL.md
│       └── scripts/
├── development/
│   ├── code-review/
│   └── debugging/
└── ...
```

### 2. 可选技能（Optional Skills）
官方提供但默认不激活，存储在 `optional-skills/` 目录：

```
optional-skills/
├── mlops/
│   ├── flash-attention/
│   ├── faiss/
│   └── pytorch-lightning/
├── blockchain/
│   ├── base/
│   └── solana/
├── communication/
├── health/
└── ...
```

用户通过 `hermes skills install official/mlops/faiss` 安装。

### 3. 用户技能（User Skills）
用户自行创建或从 Skills Hub 安装的技能：

```
~/.hermes/skills/
├── my-custom-skill/
│   └── SKILL.md
└── hub-installed-skill/
    ├── SKILL.md
    └── scripts/
        └── helper.py
```

## SKILL.md 文件结构

每个技能的核心是一个 `SKILL.md` 文件，包含 YAML frontmatter 和 Markdown 内容：

```yaml
---
name: my-skill
description: Brief description (shown in skill search results)
version: 1.0.0
author: Your Name
license: MIT
platforms: [macos, linux]          # 可选：限制操作系统
required_environment_variables:    # 可选：安全设置向导
  - name: MY_API_KEY
    prompt: API key
    help: Where to get it
    required_for: full functionality
prerequisites:                     # 可选：旧版兼容
  env_vars: [MY_API_KEY]
  commands: [curl, jq]
metadata:
  hermes:
    tags: [Category, Subcategory]
    related_skills: [other-skill]
    fallback_for_toolsets: [web]       # 当 web 工具集不可用时显示
    requires_toolsets: [terminal]      # 当 terminal 可用时才显示
    fallback_for_tools: [web_search]   # 当特定工具不可用时显示
    requires_tools: [terminal]         # 需要特定工具才显示
---
```

## 技能的发现和加载

### 阶段 1：扫描（Agent 初始化时）

**文件**: `agent/prompt_builder.py:build_skills_system_prompt()`

系统扫描以下目录：
1. `~/.hermes/skills/`（用户技能）
2. `skills/`（捆绑技能，安装时复制）
3. `optional-skills/`（可选技能）
4. `config.yaml` 中配置的 `skills.external_dirs`（外部目录）

### 阶段 2：过滤

每个技能经过多层过滤：

```
所有 SKILL.md 文件
    │
    ├──→ 平台过滤：skill_matches_platform()
    │     检查 frontmatter 中的 platforms 字段
    │     如果不匹配当前 OS → 跳过
    │
    ├──→ 禁用检查：get_disabled_skill_names()
    │     读取 config.yaml 中的 disabled_skills 列表
    │     如果被禁用 → 跳过
    │
    ├──→ 条件检查：_skill_should_show()
    │     检查 fallback_for_toolsets / requires_toolsets
    │     检查 fallback_for_tools / requires_tools
    │     根据当前可用工具/工具集决定是否显示
    │
    └──→ 通过 → 加入系统提示
```

### 阶段 3：构建索引

通过过滤的技能被组织成索引格式：

```markdown
# Available Skills

## research
- **arxiv**: Search and browse arXiv papers
- **web-research**: Comprehensive web research with citations

## development
- **code-review**: Review code for bugs, security issues, and best practices
- **debugging**: Systematic debugging methodology
```

这个索引注入到 **System Prompt** 中，让 Agent 知道有哪些技能可用。

## 技能的加载时机

### System Prompt 中的索引

索引只包含技能的**名称和描述**，不包含完整内容。这是为了：
1. 保持 System Prompt 精简
2. 利用 prompt cache（索引变化不大）

**代码**: `agent/prompt_builder.py`
```python
def build_skills_system_prompt(available_tools, available_toolsets) -> str:
    # 两层缓存：
    # 1. 内存 LRU 缓存（keyed by tools/toolsets/platform）
    # 2. 磁盘快照（.skills_prompt_snapshot.json）
    # 两层都 miss 时才进行完整的文件系统扫描
```

### 按需加载完整内容

当 Agent 决定使用某个技能时：

1. Agent 发送消息包含 `/<skill-name>` 命令
2. 技能命令处理器加载完整的 `SKILL.md` 内容
3. 内容作为**用户消息**注入（不是 System Prompt！）
4. 这保持了 System Prompt 的缓存稳定

**代码**: `agent/skill_commands.py`
```python
def _load_skill_payload(skill_name, task_id):
    skill_md = find_skill_file(skill_name)
    frontmatter, body = parse_frontmatter(skill_md.read_text())
    return body, skill_dir, display_name

def _build_skill_message(skill_content, skill_dir, system_note):
    return f"{system_note}\n\n{skill_content}"
```

## 条件加载详解

### fallback_for_toolsets（回退）
```yaml
metadata:
  hermes:
    fallback_for_toolsets: [web]
```
**语义**：当 `web` 工具集**不可用**时才显示这个技能。

**用途**：免费替代品。例如 DuckDuckGo 搜索技能在 Firecrawl（付费 web 工具）不可用时激活。

### requires_toolsets（依赖）
```yaml
metadata:
  hermes:
    requires_toolsets: [terminal]
```
**语义**：当 `terminal` 工具集**可用**时才显示这个技能。

**用途**：依赖特定能力的技能。例如智能家居控制技能需要终端访问。

### 组合使用
```yaml
metadata:
  hermes:
    fallback_for_toolsets: [browser]
    requires_toolsets: [terminal]
```
**语义**：需要 terminal，且仅在 browser 不可用时显示。

## 技能的生命周期

### 1. 发现 → 2. 索引 → 3. 激活 → 4. 使用

```
Agent 启动
    │
    ├── build_skills_system_prompt()
    │     扫描所有技能，过滤，构建索引
    │     索引注入到 System Prompt
    │
用户: "/arxiv search quantum computing"
    │
    ├── process_command("arxiv")
    │     解析为技能命令
    │
    ├── _load_skill_payload("arxiv")
    │     找到 arxiv/SKILL.md
    │     解析 frontmatter + body
    │
    ├── _build_skill_message(body, dir, note)
    │     构建用户消息
    │
    └── run_conversation(user_message + skill_content)
          Agent 按照技能指令执行
```

## 技能的自我创建

Hermes 的独特之处：Agent 可以**自己创建技能**！

当 Agent 完成一个复杂任务后，会被提示创建新技能：

```
Agent: "我刚刚完成了一个复杂的数据分析流程。让我创建一个技能来记住这个过程..."
     → 在 ~/.hermes/skills/data-analysis/ 创建 SKILL.md
     → 写入步骤、注意事项、常见错误
```

下次遇到类似任务时，Agent 会自动发现并使用这个新技能。

## 技能 vs 工具的区别

| 维度 | 技能（Skill） | 工具（Tool） |
|------|--------------|-------------|
| 实现方式 | Markdown 指令 + 现有工具 | Python 代码 |
| 注册方式 | 文件系统发现 | `registry.register()` |
| 加载时机 | 按需（`/<skill-name>`） | 始终可用（如果在工具集中） |
| 灵活性 | 高（LLM 解释指令） | 精确（代码执行） |
| 适合场景 | 流程性任务、领域知识 | API 集成、二进制数据处理 |
| 贡献方式 | 上传到 Skills Hub | 修改代码仓库 |

**经验法则**：90% 的新功能应该作为**技能**添加，而不是工具。

## 技能的缓存机制

**文件**: `agent/prompt_builder.py`

技能索引使用两层缓存：

1. **内存 LRU 缓存**：
   - Key: `(skills_dir, external_dirs, available_tools, available_toolsets, platform)`
   - 命中时直接返回，无需文件系统操作

2. **磁盘快照**（`.skills_prompt_snapshot.json`）：
   - 包含所有技能的元数据（名称、描述、分类、平台、条件）
   - 通过 mtime/size 清单验证有效性
   - 进程重启后仍然有效

只有两层都 miss 时才会进行完整的文件系统扫描 + 重新构建快照。
