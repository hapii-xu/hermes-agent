# 05 - 存储系统

> Hermes 如何持久化数据：SQLite、JSON 日志、配置文件

## 概览

Hermes 使用多种存储机制来持久化不同类型的数据：

```
~/.hermes/
├── state.db           # SQLite — 会话元数据 + FTS5 搜索
├── sessions/          # JSONL — 完整对话日志
├── memories/          # Markdown — 记忆文件
│   ├── MEMORY.md
│   └── USER.md
├── skills/            # 目录 — 用户技能
├── config.yaml        # YAML — 配置
├── .env               # ENV — API 密钥
├── auth.json          # JSON — OAuth 凭证
├── cron/              # 目录 — 定时任务
└── logs/              # 目录 — 运行日志
```

## 1. SQLite 会话数据库（state.db）

**文件**: `hermes_state.py`

### 数据库 Schema

```sql
-- 会话表
CREATE TABLE sessions (
    id TEXT PRIMARY KEY,              -- UUID
    source TEXT NOT NULL,             -- "cli", "telegram", "discord", ...
    user_id TEXT,                     -- 平台用户 ID
    model TEXT,                       -- 使用的模型
    model_config TEXT,                -- JSON 模型配置
    system_prompt TEXT,               -- 系统提示词（用于缓存复用）
    parent_session_id TEXT,           -- 父会话 ID（压缩后创建新会话）
    started_at REAL NOT NULL,         -- 开始时间戳
    ended_at REAL,                    -- 结束时间戳
    end_reason TEXT,                  -- 结束原因
    message_count INTEGER DEFAULT 0,  -- 消息数
    tool_call_count INTEGER DEFAULT 0,
    input_tokens INTEGER DEFAULT 0,   -- 输入 token 统计
    output_tokens INTEGER DEFAULT 0,  -- 输出 token 统计
    cache_read_tokens INTEGER DEFAULT 0,
    cache_write_tokens INTEGER DEFAULT 0,
    reasoning_tokens INTEGER DEFAULT 0,
    estimated_cost_usd REAL,          -- 预估费用
    title TEXT,                       -- 会话标题（自动生成）
    -- ... 更多字段
);

-- 消息表
CREATE TABLE messages (
    id INTEGER PRIMARY KEY AUTOINCREMENT,
    session_id TEXT NOT NULL REFERENCES sessions(id),
    role TEXT NOT NULL,               -- "system", "user", "assistant", "tool"
    content TEXT,
    tool_call_id TEXT,
    tool_calls TEXT,                  -- JSON 工具调用列表
    tool_name TEXT,
    timestamp REAL NOT NULL,
    token_count INTEGER,
    reasoning TEXT,                   -- 推理内容
    reasoning_details TEXT,           -- 推理详情
);

-- FTS5 全文搜索
CREATE VIRTUAL TABLE messages_fts USING fts5(
    content,
    content=messages,
    content_rowid=id
);
```

### WAL 模式

```python
self._conn.execute("PRAGMA journal_mode=WAL")
```

**WAL（Write-Ahead Logging）** 允许：
- 多个读者同时读取
- 一个写入者写入
- 不阻塞读取操作

这对于 Gateway 模式很重要（多个平台适配器可能同时访问数据库）。

### 写入竞争处理

多个 Hermes 进程（Gateway + CLI 会话 + 后台 Agent）共享一个数据库时，WAL 写入锁竞争会导致 TUI 冻结。

解决方案：**应用层随机退避重试**

```python
_WRITE_MAX_RETRIES = 15
_WRITE_RETRY_MIN_S = 0.020   # 20ms
_WRITE_RETRY_MAX_S = 0.150   # 150ms

def _execute_write(self, fn):
    for attempt in range(self._WRITE_MAX_RETRIES):
        try:
            with self._lock:
                self._conn.execute("BEGIN IMMEDIATE")
                result = fn(self._conn)
                self._conn.commit()
            return result
        except sqlite3.OperationalError as exc:
            if "locked" in str(exc).lower():
                time.sleep(random.uniform(0.020, 0.150))  # 随机退避
                continue
```

**为什么用随机退避而不是 SQLite 内置的 busy handler？**
SQLite 的确定性退避会导致"车队效应"（convoy）— 多个写入者同步等待，依次执行。随机退避自然错开竞争者。

### FTS5 全文搜索

```sql
-- 搜索包含 "python" 的对话消息
SELECT m.* FROM messages m
JOIN messages_fts fts ON m.id = fts.rowid
WHERE messages_fts MATCH 'python'
LIMIT 10;
```

用于 `session_search` 工具，让 Agent 能搜索过去的对话。

### 会话压缩的链式关系

当对话太长需要压缩时：
1. 创建新的 `session_id`
2. 将 `parent_session_id` 指向原会话
3. 压缩后的消息写入新会话

```
session_A (原始会话，500 条消息)
    │ parent_session_id = NULL
    ↓ compression
session_B (压缩后，50 条消息)
    │ parent_session_id = session_A
    ↓ compression
session_C (再次压缩，25 条消息)
    │ parent_session_id = session_B
```

这允许 `session_search` 工具在搜索时追溯到完整的原始对话。

### SessionDB 类核心方法

| 方法 | 作用 |
|------|------|
| `upsert_session()` | 插入或更新会话元数据 |
| `save_message()` | 追加消息到会话 |
| `save_batch_messages()` | 批量保存消息 |
| `load_transcript()` | 加载完整对话历史 |
| `search_messages()` | FTS5 全文搜索 |
| `get_session()` | 获取会话元数据 |
| `update_token_counts()` | 更新 token 统计 |
| `update_system_prompt()` | 更新系统提示词（用于缓存复用） |

## 2. JSON 会话日志（sessions/）

**位置**: `~/.hermes/sessions/{session_id}.jsonl`

每个会话有一个独立的 JSONL 文件，存储完整的对话内容（包括工具调用）。

### 格式

```jsonl
{"role": "system", "content": "You are Hermes...", "timestamp": 1234567890.0}
{"role": "user", "content": "帮我查天气", "timestamp": 1234567891.0}
{"role": "assistant", "content": null, "tool_calls": [...], "timestamp": 1234567892.0}
{"role": "tool", "tool_call_id": "call_abc", "tool_name": "web_search", "content": "{\"results\": [...]}", "timestamp": 1234567893.0}
{"role": "assistant", "content": "今天北京天气晴...", "timestamp": 1234567894.0}
```

### 与 SQLite 的区别

| | SQLite (state.db) | JSONL (sessions/) |
|--|-----------------|-------------------|
| 用途 | 会话元数据 + 搜索 | 完整对话日志 |
| 结构 | 关系型 | 行式 JSON |
| 大小 | 较小（元数据） | 较大（完整内容） |
| 查询 | SQL + FTS5 | 顺序读取 |
| 使用场景 | `/insights`、会话列表 | 恢复对话、训练数据 |

## 3. 记忆文件（memories/）

**位置**: `~/.hermes/memories/`

详见 [03-记忆系统.md](./03-记忆系统.md)


- 字符限制（MEMORY: 2200 字符，USER: 1375 字符）
- 写入时使用文件锁 + 原子替换

## 4. 配置文件

### config.yaml

**位置**: `~/.hermes/config.yaml`
**示例**: `cli-config.yaml.example`（仓库根目录）

```yaml
model:
  default: "anthropic/claude-sonnet-4.6"
  provider: "openrouter"

terminal:
  backend: "local"         # local, docker, ssh, modal, daytona, singularity
  timeout: 300

compression:
  enabled: true
  threshold: 0.5           # 50% 上下文时触发压缩

display:
  skin: "default"
  show_reasoning: false

memory:
  nudge_interval: 15       # 每 15 回合提醒整理记忆

session_reset:
  idle_minutes: 120        # 空闲 2 小时后自动重置
  at_hour: 4               # 每天 4 点自动重置

skills:
  disabled: []
  external_dirs: []
```

### .env

**位置**: `~/.hermes/.env`

```bash
OPENROUTER_API_KEY=sk-or-v1-...
ANTHROPIC_API_KEY=sk-ant-...
TELEGRAM_BOT_TOKEN=123456:ABC-DEF...
```

### 配置加载系统

有两个独立的配置加载器：

| 加载器 | 使用者 | 位置 |
|--------|--------|------|
| `load_cli_config()` | CLI 模式 | `cli.py` |
| `load_config()` | `hermes tools`、`hermes setup` | `hermes_cli/config.py` |
| 直接 YAML 加载 | Gateway | `gateway/run.py` |

## 5. Profile 多实例隔离

Hermes 支持通过 `HERMES_HOME` 环境变量创建多个完全隔离的实例：

```bash
# 默认实例
hermes                           # 使用 ~/.hermes/

# 编码专用实例
HERMES_HOME=~/.hermes/profiles/coder hermes -p coder

# 研究专用实例
HERMES_HOME=~/.hermes/profiles/research hermes -p research
```

每个实例有独立的：
- 配置（config.yaml）
- API 密钥（.env）
- 记忆（MEMORY.md、USER.md）
- 会话（state.db、sessions/）
- 技能（skills/）

### 代码规则

```python
# ✅ 正确：使用 get_hermes_home()
from hermes_constants import get_hermes_home
config_path = get_hermes_home() / "config.yaml"

# ❌ 错误：硬编码路径（会破坏 Profile 隔离）
config_path = Path.home() / ".hermes" / "config.yaml"
```

所有 119+ 处 `get_hermes_home()` 引用都会自动指向当前 Profile 的目录。

## 存储数据流图

```
用户发送消息
    │
    ├──→ 检查 SQLite state.db 中的会话
    │     如果新会话 → INSERT INTO sessions
    │
    ├──→ 加载 JSONL 对话历史
    │     sessions/{session_id}.jsonl → 消息列表
    │
    ├──→ 加载记忆文件
    │     memories/MEMORY.md → 冻结快照
    │     memories/USER.md   → 冻结快照
    │
    ├──→ Agent 执行（对话 + 工具调用）
    │
    ├──→ 写入 SQLite state.db
    │     UPDATE sessions SET message_count=?, input_tokens=?...
    │     INSERT INTO messages ...
    │
    ├──→ 追加 JSONL
    │     sessions/{session_id}.jsonl += 新消息行
    │
    └──→ 可能的记忆写入
          memories/MEMORY.md += 新条目（memory tool 调用）
```
