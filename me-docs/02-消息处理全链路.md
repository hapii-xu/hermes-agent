# 02 - 消息处理全链路

> 从用户发送消息到 AI 响应的完整流程

## 真实场景

**场景**：用户通过 Telegram 给 Hermes 发送消息："帮我查一下今天的天气"

这个简单的消息，在 Hermes 内部经历了以下完整链路：

```
用户 Telegram → Telegram Adapter → GatewayRunner → AIAgent → LLM API → Tool → Response
```

---

## 阶段 1：平台接收消息

**文件**: `gateway/platforms/telegram.py`

Telegram 的 webhook 或 polling 接收到消息后，平台适配器将其包装为 `MessageEvent` 对象：

```python
MessageEvent(
    text="/weather 北京",       # 消息文本（可能包含 slash 命令）
    message_type=MessageType.TEXT,
    source=MessageSource(
        platform=Platform.TELEGRAM,
        user_id="123456789",
        user_name="zhangsan",
        chat_id="123456789",
        chat_type="dm",
    ),
    message_id="msg_abc123",
)
```

## 阶段 2：GatewayRunner._handle_message()

**文件**: `gateway/run.py`，行 2655-2927

Gateway 收到 `MessageEvent` 后，进入核心消息处理管道：

### 2.1 用户授权检查
```python
if not self._is_user_authorized(source):
    # 未授权用户：在 DM 中提供配对码，在群组中静默忽略
    code = self.pairing_store.generate_code(...)
    await adapter.send(chat_id, f"Here's your pairing code: `{code}`")
    return None
```

### 2.2 命令拦截
如果会话正在运行 Agent（AI 正在执行工具调用），特殊命令会优先处理：

| 命令 | 行为 |
|------|------|
| `/stop` | 中断当前 Agent，释放会话锁 |
| `/reset` / `/new` | 中断 Agent，创建新会话 |
| `/queue` | 将消息排队，不打断当前执行 |
| `/approve` / `/deny` | 直接路由到审批处理器 |
| `/status` | 返回当前运行状态 |

对于普通消息，会**中断当前运行的 Agent**：
```python
running_agent.interrupt(event.text)  # 设置中断标志
self._pending_messages[_quick_key] = event.text  # 消息排队
```

### 2.3 Slash 命令分发
```python
command = event.get_command()  # 解析 "/weather" → "weather"
if command in GATEWAY_KNOWN_COMMANDS:
    await self.hooks.emit("command:weather", {...})
```

## 阶段 3：SessionStore — 会话管理

**文件**: `gateway/session.py`

### 3.1 获取或创建会话
```python
session_entry = self.session_store.get_or_create_session(source)
# session_key = "telegram:dm:123456789"
# session_id  = "uuid-xxxx-xxxx"
```

会话 key 的格式：`{platform}:{chat_type}:{user_id}`

### 3.2 加载历史对话
```python
history = self.session_store.load_transcript(session_entry.session_id)
# 返回: [{"role": "user", "content": "你好"}, {"role": "assistant", "content": "你好！有什么可以帮助你的？"}, ...]
```

历史对话存储在 `~/.hermes/sessions/{session_id}.jsonl` 文件中。

### 3.3 会话卫生检查（自动压缩）
如果历史对话太大（超过模型上下文的 85%），会自动压缩：
```python
if _approx_tokens >= _compress_token_threshold:
    # 创建一个临时 AIAgent，仅用于压缩
    _hyg_agent = AIAgent(max_iterations=4, enabled_toolsets=["memory"], ...)
    _compressed, _ = _hyg_agent._compress_context(_hyg_msgs, ...)
    self.session_store.rewrite_transcript(session_entry.session_id, _compressed)
```

## 阶段 6：创建 AIAgent 并执行

**文件**: `gateway/run.py`，`_run_agent()`

### 6.1 创建 AIAgent 实例
```python
agent = AIAgent(
    model="anthropic/claude-opus-4-6",
    max_iterations=90,
    enabled_toolsets=["web", "terminal", "file", "browser", "memory", ...],
    platform="telegram",
    session_id=session_entry.session_id,
    session_db=session_db,       # SQLite 数据库连接
    quiet_mode=True,             # Gateway 模式下静默
    step_callback=...,           # 网关钩子
    stream_delta_callback=...,   # 流式输出回调
    ...
)
```

### 6.2 调用 run_conversation()
**文件**: `run_agent.py`，行 7796

这是**核心函数**，完整流程如下：

```
run_conversation(user_message)
├── 1. 初始化迭代预算 (IterationBudget(90))
├── 2. 构建 System Prompt（仅首次调用，之后复用缓存）
├── 3. 预检上下文压缩（如果消息已接近上限）
├── 4. 记忆预取 (memory_manager.prefetch_all(user_message))
├── 5. 主对话循环 (while api_call_count < max_iterations)
│   ├── 5a. 准备 API 消息（注入记忆、插件上下文）
│   ├── 5b. 应用 Anthropic 缓存控制
│   ├── 5c. 调用 LLM API（流式或非流式）
│   ├── 5d. 解析响应
│   │   ├── 如果有 tool_calls → 进入 5e
│   │   └── 如果是文本响应 → 结束循环
│   ├── 5e. 执行工具 (handle_function_call)
│   │   ├── 并行执行（如果安全）
│   │   └── 顺序执行（如果有依赖）
│   ├── 5f. 将工具结果添加到消息
│   └── 5g. 循环回 5a
├── 6. 持久化会话到 SQLite
├── 7. 同步记忆 (memory_manager.sync_all)
├── 8. 技能触发检查（是否需要创建新技能）
└── 9. 返回 final_response
```

## 阶段 7：System Prompt 构建（首次调用）

**文件**: `run_agent.py:_build_system_prompt()` → `agent/prompt_builder.py`

System Prompt 由多个部分组成：

```
┌─────────────────────────────────────────────┐
│  Agent Identity (agent/prompt_builder.py)     │
│  "You are Hermes, a helpful AI assistant..."  │
├─────────────────────────────────────────────┤
│  Tool Use Enforcement                       │
│  "When using tools, follow these rules..."   │
├─────────────────────────────────────────────┤
│  Skills (build_skills_system_prompt)         │
│  [已激活技能的 SKILL.md 内容]                │
├─────────────────────────────────────────────┤
│  Context Files (build_context_files_prompt)  │
│  [AGENTS.md, CLAUDE.md 等项目文件]           │
├─────────────────────────────────────────────┤
│  Memory Provider System Prompt              │
│  [MEMORY.md 的使用指南]                      │
├─────────────────────────────────────────────┤
│  Soul / Personality (load_soul_md)          │
│  [SOUL.md — 个性文件]                       │
├─────────────────────────────────────────────┤
│  Environment Hints                          │
│  [OS、Python 版本、当前目录]                 │
└─────────────────────────────────────────────┘
```

**重要**：System Prompt 在首次调用后会被**缓存**，后续调用直接复用，以利用 Anthropic 的 prompt cache（减少 75% 的输入 token 成本）。

## 阶段 8：LLM API 调用

**文件**: `run_agent.py:_interruptible_streaming_api_call()`

### 8.1 构建 API 参数
```python
api_kwargs = self._build_api_kwargs(api_messages)
# {
#     "model": "claude-opus-4-6",
#     "messages": [{"role": "system", "content": "..."}, {"role": "user", "content": "..."}],
#     "tools": [...],  # 工具 schema 列表
#     "max_tokens": 8192,
#     "stream": True,
# }
```

### 8.2 调用 API
支持两种模式：
- **OpenAI 兼容**：`client.chat.completions.create()`
- **Anthropic 原生**：`client.messages.create()`

调用时会显示 spinner 动画：
```
(◕‿◕) forging...
```

### 8.3 重试机制
如果 API 调用失败，最多重试 3 次，使用退避策略：
- 429（限流）→ 立即切换 fallback 模型
- 5xx（服务器错误）→ 退避重试
- Unicode 编码错误 → 自动清理后重试

## 阶段 9：工具调用与 Dispatch

**文件**: `model_tools.py:handle_function_call()` → `tools/registry.py:dispatch()`

当 LLM 返回 `tool_calls` 时：

### 9.1 并行性检查
```python
if _should_parallelize_tool_batch(tool_calls):
    # 安全并行：读取独立文件、只读工具
    with ThreadPoolExecutor(max_workers=8) as executor:
        futures = [executor.submit(dispatch, ...) for tc in tool_calls]
else:
    # 顺序执行：有依赖或修改操作
    for tc in tool_calls:
        result = dispatch(tool_name, args)
```

### 9.2 工具分发
```python
# tools/registry.py:dispatch()
entry = self._tools.get(name)  # 查找已注册的工具
result = entry.handler(args, **kwargs)  # 执行
return json.dumps(result)  # 返回 JSON 字符串
```

### 9.3 常见工具示例
对于 "帮我查一下今天的天气"，Agent 可能调用：

1. `web_search(query="北京 今日天气")` — 搜索天气
2. `web_extract(url="https://weather.com/...")` — 提取网页内容
3. 最终返回文本响应

## CLI 模式 vs Gateway 模式的区别

| 方面 | CLI | Gateway |
|------|-----|---------|
| 入口 | `cli.py:HermesCLI` | `gateway/run.py:GatewayRunner` |
| AIAgent 生命周期 | 持久化（整个 CLI 会话） | 每次消息创建新实例 |
| System Prompt 缓存 | 整个对话中复用 | 通过 SQLite 存储复用 |
| 工具输出 | 终端直接显示 | 通过平台 adapter.send() |
| 流式输出 | prompt_toolkit 组件 | stream_delta_callback → adapter |
| 审批机制 | 同步 input() | 阻塞式 /approve /deny |
| 会话 key | `cli:local` | `{platform}:{chat_type}:{user_id}` |
