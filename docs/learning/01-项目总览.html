一、一句话定位

Hermes Agent 是 Nous Research 开源的 "自我改进型（self-improving）个人 AI agent"。

它最大的特点是带有一个内建的学习闭环：在使用过程中，它会：

  • 从经验中创建技能（skills），并在使用中自我改进这些技能；
  • 主动 nudge 自己把知识持久化到记忆里；
  • 检索自己过去的对话（FTS5 全文检索）；
  • 跨会话逐步建立"你是谁"的用户画像。
一句话总结：别的 agent 用完即忘，Hermes 会越用越懂你、越用越能干。
项目元信息值
仓库NousResearch/hermes-agent，License：MIT
语言Python（requires-python = ">=3.11,<3.14"），当前版本 0.17.0（pyproject.toml:10）
依赖管理uv + uv.lock（精确锁定版本，供应链安全考量）

二、它解决什么问题 / 有什么特点

能力说明
任意模型，无锁定支持 Nous Portal / OpenRouter（200+ 模型）/ NovitaAI / NVIDIA NIM / Kimi / GLM / OpenAI / 自建端点等。hermes model 一键切换，无需改代码。
真正的终端界面（TUI）多行编辑、slash 命令自动补全、对话历史、中断并改向、流式工具输出。
活在你常用的地方单个 gateway 进程同时驱动 Telegram、Discord、Slack、WhatsApp、Signal、CLI 等 ~20 个平台；语音转写、跨平台会话连续。
闭环学习agent 策展的记忆 + 周期性 nudge；复杂任务后自动造技能；技能使用中自我改进；跨会话召回。兼容 agentskills.io 开放标准。
定时自动化内建 cron 调度器，用自然语言描述定时任务并投递到任意平台（日报、夜间备份、每周审计等）。
委派与并行spawn 隔离的子 agent 跑并行工作流；用 Python 脚本通过 RPC 调用工具，把多步流水线压成"零上下文开销"的一轮。
到处都能跑六种终端后端：本地、Docker、SSH、Singularity、Modal、Daytona。Modal/Daytona 支持 serverless 持久化——空闲时休眠、按需唤醒，几乎不花钱。
研究友好批量轨迹生成、轨迹压缩，用于训练下一代工具调用模型。

三、两条贯穿全局的设计铁律

理解这两条，你才能读懂代码里大量看似"绕"的设计。出处：AGENTS.md 开头。

①

逐对话的提示缓存是神圣的（Per-conversation prompt caching is sacred）

一个长对话每一轮都复用缓存好的前缀。任何"改动过去上下文 / 中途换工具集 / 重建系统提示"的行为都会让缓存失效，使用户成本成倍上涨。所以系统提示必须在整个对话生命周期内逐字节稳定（byte-stable），唯一例外是上下文压缩。

②

核心是"窄腰"，能力长在边缘（The core is a narrow waist; capability lives at the edges）

每加一个核心工具（model tool），它就会出现在每一次 API 调用里，因此新增核心工具的门槛极高。绝大多数新能力应该以 CLI 命令 + 技能、service-gated 工具或插件的形式出现，而不是往核心里塞东西。

足迹阶梯（Footprint Ladder）

从最省到最贵：选最高（足迹最小）且能解决问题的那级。出处：AGENTS.md:171-196。

  1. 1
    扩展已有代码能力只是已有东西的变体，零新增足迹。
  2. 2
    CLI 命令 + skill零 model-tool 足迹，订阅/定时任务/服务安装的默认选择。
  3. 3
    Service-gated tool（check_fn）前置条件不满足时零足迹（如 HA 工具需要 token）。
  4. 4
    Plugin第三方/小众/用户特定能力，住在 ~/.hermes/plugins/，运行时发现。
  5. 5
    MCP server（进 catalog）需要是工具但非内核基础，零永久 core-schema 足迹，任何 MCP host 可复用。
  6. 6
    新 core tool（最后手段）基础性、几乎所有用户都广泛需要、terminal+file 无法触达。永久 schema 足迹。

五、配置体系（务必先搞清楚）

出处：AGENTS.md:103-107。两者职责严格分离，这是项目的硬规则：

config.yaml（示例 cli-config.yaml.example）.env（示例 .env.example）
存什么所有行为设置：默认模型、provider、超时、阈值、功能开关、显示偏好……只存机密：API key、token、密码。
位置~/.hermes/config.yaml（profile 感知）~/.hermes/.env
谁改hermes setup / hermes model 等命令，或手改 YAML用户填入凭证
硬性约束：禁止为非机密配置新增 HERMES_* 环境变量。一切行为开关都进 config.yaml。任何告诉用户"把 X 设进 .env"的 PR 会被拒——除非 X 是凭证。

记忆口诀：凭证进 .env，行为进 config.yaml。

运行时的家目录是 HERMES_HOME（通常 ~/.hermes），git 检出位于 $HERMES_HOME/hermes-agent。

六、技术栈速览（来自 pyproject.toml）

模型 SDK

openai（统一 OpenAI 兼容接口），可选 anthropic、boto3(bedrock)、mistralai 等按需懒加载。

CLI / TUI

fire（命令解析）、prompt_toolkit（交互输入）、rich（渲染）、simple-term-menu。

网关 / 服务

fastapi + uvicorn、python-telegram-bot、discord.py、slack-bolt、mautrix（matrix）等。

调度 / MCP

croniter（cron）、mcp + starlette（MCP server）。

跨平台

psutil、pywinpty(Win) / ptyprocess(POSIX)、tzdata(Win)、concurrent-log-handler(Win 日志轮转)。

健壮性

tenacity（重试）、pydantic（校验）、httpx（HTTP 客户端）。

依赖策略：每个直接依赖都精确钉死到 ==X.Y.Z（不用范围），并配 uv.lock。原因是供应链安全——2026-05 的 mistralai 投毒蠕虫事件后收紧（见 pyproject.toml:24 起的大段注释）。新增/升级依赖必须改 pin 并重新 uv lock。
