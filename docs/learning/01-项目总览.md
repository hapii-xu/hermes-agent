# 01 · 项目总览

> **本章导读**：用最短的篇幅让你建立对 Hermes Agent 的"全局心智模型"——它是什么、解决什么问题、由哪些大块组成、用什么技术栈。读完这一章，你应该能向别人用三句话讲清楚这个项目。后续章节再逐层深入。

---

## 1. 一句话定位

**Hermes Agent** 是 [Nous Research](https://nousresearch.com) 开源的 **"自我改进型（self-improving）个人 AI agent"**。

它最大的特点是带有一个**内建的学习闭环**：在使用过程中，它会

- 从经验中**创建技能（skills）**，并在使用中**自我改进**这些技能；
- **主动 nudge 自己**把知识持久化到记忆里；
- **检索自己过去的对话**（FTS5 全文检索；README 称含 LLM 摘要，但当前代码已精简该路径，详见第 4 章）；
- 跨会话**逐步建立"你是谁"的用户画像**。

一句话：**别的 agent 用完即忘，Hermes 会越用越懂你、越用越能干。**

- 仓库：`NousResearch/hermes-agent`，License：MIT
- 语言：Python（`requires-python = ">=3.11,<3.14"`），当前版本 `0.17.0`（见 `pyproject.toml:10`）
- 依赖管理：`uv` + `uv.lock`（精确锁定版本，供应链安全考量）

## 2. 它解决什么问题 / 有什么特点

| 能力 | 说明 |
| --- | --- |
| **任意模型，无锁定** | 支持 Nous Portal / OpenRouter（200+ 模型）/ NovitaAI / NVIDIA NIM / Kimi / GLM / OpenAI / 自建端点等。`hermes model` 一键切换，无需改代码。 |
| **真正的终端界面（TUI）** | 多行编辑、slash 命令自动补全、对话历史、中断并改向、流式工具输出。 |
| **活在你常用的地方** | 单个 gateway 进程同时驱动 Telegram、Discord、Slack、WhatsApp、Signal、CLI 等 ~20 个平台；语音转写、跨平台会话连续。 |
| **闭环学习** | agent 策展的记忆 + 周期性 nudge；复杂任务后自动造技能；技能使用中自我改进；跨会话召回。兼容 [agentskills.io](https://agentskills.io) 开放标准。 |
| **定时自动化** | 内建 cron 调度器，用自然语言描述定时任务并投递到任意平台（日报、夜间备份、每周审计等）。 |
| **委派与并行** | spawn 隔离的子 agent 跑并行工作流；用 Python 脚本通过 RPC 调用工具，把多步流水线压成"零上下文开销"的一轮。 |
| **到处都能跑** | 六种终端后端：本地、Docker、SSH、Singularity、Modal、Daytona。Modal/Daytona 支持 serverless 持久化——空闲时休眠、按需唤醒，几乎不花钱。$5 VPS 或 GPU 集群都能跑。 |
| **研究友好** | 批量轨迹生成、轨迹压缩，用于训练下一代工具调用模型。 |

## 3. 两条贯穿全局的设计铁律

理解这两条，你才能读懂代码里大量看似"绕"的设计（出处：`AGENTS.md` 开头）。

1. **逐对话的提示缓存是神圣的（Per-conversation prompt caching is sacred）。**
   一个长对话每一轮都复用缓存好的前缀。任何"改动过去上下文 / 中途换工具集 / 重建系统提示"的行为都会让缓存失效，使用户成本成倍上涨。**所以系统提示必须在整个对话生命周期内逐字节稳定（byte-stable）**，唯一例外是上下文压缩。

2. **核心是"窄腰"，能力长在边缘（The core is a narrow waist; capability lives at the edges）。**
   每加一个**核心工具（model tool）**，它就会出现在**每一次** API 调用里，因此新增核心工具的门槛极高。绝大多数新能力应该以 **CLI 命令 + 技能**、**service-gated 工具**或**插件**的形式出现，而不是往核心里塞东西。

> 记住这张优先级阶梯（"Footprint Ladder"）：
> **扩展已有代码 → CLI 命令 + skill → service-gated 工具 → 插件 → MCP server → 新核心工具（最后手段）**

## 4. 顶层结构地图（先有个印象）

项目根目录是一堆"大文件 + 大目录"的混合。下面按职责分组：

## 5. 配置体系（务必先搞清这条铁律）

出处：`AGENTS.md`。

- **`.env`（见 `.env.example`）只放 secrets**：API key、token、密码。
- **所有行为配置都进 `config.yaml`（见 `cli-config.yaml.example`）**：超时、阈值、feature flag、显示偏好等。

> 项目明确**拒绝**为非 secret 配置新增 `HERMES_*` 环境变量。文档面向用户时一律指向 `config.yaml`。

运行时的家目录是 `HERMES_HOME`（通常 `~/.hermes`），git 检出位于 `$HERMES_HOME/hermes-agent`。

## 6. 技术栈速览（来自 `pyproject.toml`）

- **模型 SDK**：`openai`（统一 OpenAI 兼容接口），可选 `anthropic`、`boto3`(bedrock)、`mistralai` 等按需懒加载。
- **CLI / TUI**：`fire`（命令解析）、`prompt_toolkit`（交互输入）、`rich`（渲染）、`simple-term-menu`。
- **网关 / 服务**：`fastapi` + `uvicorn`、`python-telegram-bot`、`discord.py`、`slack-bolt`、`mautrix`（matrix）等。
- **调度**：`croniter`。
- **MCP**：`mcp`、`starlette`。
- **跨平台**：`psutil`、`pywinpty`(Win)/`ptyprocess`(POSIX)、`tzdata`(Win)、`concurrent-log-handler`(Win 日志轮转)。
- **健壮性**：`tenacity`(重试)、`pydantic`(校验)、`httpx`。

> 依赖策略：**每个直接依赖都精确钉死到 `==X.Y.Z`**（不用范围），并配 `uv.lock`。原因是供应链安全——2026-05 的 mistralai 投毒蠕虫事件后收紧（见 `pyproject.toml:24` 起的大段注释）。新增/升级依赖必须改 pin 并重新 `uv lock`。
