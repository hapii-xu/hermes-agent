## 1. 环境搭建（uv）

### 1.1 为什么是 uv

项目用 [`uv`](https://docs.astral.sh/uv/)（Astral 出品的 Rust 写的 Python 包管理器）管理依赖，而不是 pip/poetry。Windows 一键安装脚本（`iex (irm https://hermes-agent.nousresearch.com/install.ps1)`）会自动装好 `uv`、Python 3.11、Node.js、ripgrep、ffmpeg，以及一份**便携版 Git Bash（MinGit）**，解压到 `%LOCALAPPDATA%\hermes\git`，不需要管理员权限，也不碰你系统已有的 Git（README.md:53）。

> **Windows 杀软误报**：部分杀软（Bitdefender / Windows Defender）会把 `%LOCALAPPDATA%\hermes\bin\uv.exe` 当成病毒隔离，这是**误报**——它就是 Astral 的 `uv`。验证与加白名单步骤见 README.md:70-101（核心：把 `bin` **文件夹**加白，别加文件哈希，因为升级后哈希会变）。

### 1.2 两条安装路径

**路径 A（推荐 / 贡献者标准路径）**：先跑标准安装器，再在它克隆出的完整 git 仓库里加装开发依赖。这样你的开发环境布局和 CLI、`hermes update`、懒加载依赖、gateway 假设的布局完全一致（README.md:220-230、CONTRIBUTING.md:99-118）。完整仓库位于 `$HERMES_HOME/hermes-agent`（通常 `~/.hermes/hermes-agent`）。

**路径 B（手动 clone，本机当前就是这种）**：适合一次性 clone、容器或 CI。README.md:235-240 / CONTRIBUTING.md:135-148 给的是 bash 写法，PowerShell 等价命令如下：

```powershell
# 在仓库根目录 C:\Users\hapii\Documents\GitHub\hermes-agent 下
uv venv .venv --python 3.11           # 创建 3.11 虚拟环境到 .venv\
.\.venv\Scripts\Activate.ps1          # 激活（PowerShell）
uv pip install -e ".[all,dev]"        # 可编辑安装 + all + dev 两个 extras
npm install                           # 可选：浏览器工具 / 文档站依赖
```

> `requires-python = ">=3.11,<3.14"`（pyproject.toml:20）。**上限是有意为之**，不是摆设：uv 会用 `requires-python` 解析解释器，若不封顶，继承来的 `UV_PYTHON` 或新发行版可能选到 3.14，而 pydantic-core 等 Rust 后端在 3.14 上还没有 cp314 wheel，会退化成本地源码编译并失败。封到 `<3.14` 让 uv 直接报清晰错误而不是闷头编译（pyproject.toml:13-19）。

### 1.3 `[all,dev]` 到底装了什么 —— extras 速查

`pyproject.toml` 的 `[project.optional-dependencies]`（第 140 行起）定义了一大堆 extras，按"装哪个就拉哪个"的原则切分：

| extra | 内容 | 何时需要 |
| --- | --- | --- |
| `dev` | `debugpy`、`pytest`、`pytest-asyncio`、`mcp`、`starlette`、`ty`、`ruff`、`setuptools`（pyproject.toml:157） | **开发/调试/测试/lint 必装** |
| `all` | 一组**无法懒加载**的 extra 聚合（cron/cli/pty/mcp/web/google/youtube…，pyproject.toml:262-294） | 想要功能尽量全时装 |
| `messaging` | telegram / discord / slack / aiohttp 等（pyproject.toml:158） | 跑消息网关时 |
| `web` | fastapi / uvicorn / starlette（pyproject.toml:261） | `hermes dashboard` |
| `voice` `matrix` `mistral` … | 各后端专属 | 用到对应后端时 |

注意几个**故意做成"空壳别名"**的 extra：`cron`、`pty`、`vision`、`mistral` 等——它们的依赖要么已进核心 `dependencies`，要么走"首次使用时懒加载"（`tools/lazy_deps.py`），保留空壳只为旧的 `pip install hermes-agent[xxx]` 命令仍能解析（pyproject.toml:159、177-189）。

### 1.4 依赖锁定策略（供应链安全）—— 必读注释

`dependencies` 里每个直接依赖都是 **精确钉死 `==X.Y.Z`，没有范围**（pyproject.toml:24-44）。原因写在注释里，值得理解：

- 范围（如 `mistralai>=2.3.0,<3`）允许 PyPI 随时推一个新的传递依赖版本，**绕过我方代码评审**。精确 pin 意味着新版本只能通过"我方主动改 pin + 重新生成 `uv.lock`"才会到达用户。
- 这条策略是 **2026-05-12** 收紧的，起因是 Mini Shai-Hulud 蠕虫攻击了 PyPI 上的 `mistralai 2.4.6`；若当时用的是范围而非精确 pin，隔离前几小时内的所有安装都会拉到恶意版本。
- **改依赖的正确姿势**：改 pyproject.toml 里的 pin **并** `uv lock` 重新生成 `uv.lock`，保持传递依赖解析一致（pyproject.toml:35-37）。不要随意把范围加回来。
- `[all]` 的政策（pyproject.toml:262-283）：只收"每个 session 都可能用、agent loop 启动前就需要、或打包方（Nix/Homebrew）必须进 wheel 的"东西；任何 opt-in 后端必须**只**待在懒加载列表里——这样一个被隔离的 PyPI 版本不会拖垮所有新装机。

### 1.5 Windows 原生支持的几个关键依赖

pyproject.toml 里有几条带 `sys_platform == 'win32'` 标记的依赖，正是 Windows 原生跑通的关键：

- `pywinpty>=2.0.0,<3`（pyproject.toml:115）——Windows 下的伪终端（PTY），对应 POSIX 的 `ptyprocess`。终端工具靠它。
- `tzdata`（pyproject.toml:95）——Windows 系统不自带 IANA 时区库，Python 的 `zoneinfo` 对任何非 UTC 时区都会抛 `ZoneInfoNotFoundError`，靠这个数据包补上。
- `concurrent-log-handler`（pyproject.toml:137）——**Windows 日志轮转专用**，下文"日志系统"详述。
- `psutil`（pyproject.toml:101）——跨平台进程/PID 管理，替代在 Windows 上会"静默杀错进程"的 `os.kill(pid, 0)`。

## 2. 如何运行

### 2.1 核心命令一览

入口点定义在 `[project.scripts]`（pyproject.toml:296-299）：`hermes = hermes_cli.main:main`。安装后 `hermes` 就在 PATH 上。常用命令（README.md:107-117）：

```powershell
hermes              # 交互式 CLI —— 开一段对话（最常用）
hermes model        # 选 LLM 提供商和模型
hermes tools        # 配置启用哪些工具
hermes config set   # 设置单个配置项
hermes gateway      # 启动消息网关（Telegram / Discord 等）
hermes setup        # 完整 setup 向导（一次配好所有东西）
hermes doctor       # 诊断安装/配置问题（debug 第一站）
hermes update       # 升级到最新版
hermes debug share  # 上传脱敏后的调试报告，拿到可分享 URL
```

如果你用的是**手动 clone（路径 B）**且 `hermes` 没进 PATH，从激活的 venv 里直接调用：

```powershell
.\.venv\Scripts\hermes.exe doctor
# 或
.\.venv\Scripts\python.exe -m hermes_cli.main doctor
```

### 2.2 配置文件位置（HERMES_HOME）

所有用户配置、日志、会话库都放在 `HERMES_HOME` 指向的目录：

- 环境变量 `HERMES_HOME` 优先（hermes_constants.py:73-75）。
- 未设置时回退到平台默认值：Linux/macOS/WSL2 是 `~/.hermes`；**Windows 原生安装** 在 `%LOCALAPPDATA%\hermes`（README.md:59）。**「待确认」**：默认目录由 `_get_platform_default_hermes_home()` 决定，具体到你机器上可用 `hermes doctor` 输出确认。
- 还支持 **profile 模式**（`<root>/profiles/<name>`，hermes_constants.py:118-126）。

关键子目录（CONTRIBUTING.md:259-271）：

| 路径 | 用途 |
| --- | --- |
| `config.yaml` | 设置（模型、终端、toolsets、压缩等） |
| `.env` | API key 和密钥（**仅密钥**，见下方约束） |
| `auth.json` | OAuth 凭据（Nous Portal） |
| `logs/` | `agent.log` / `errors.log` / `gateway.log` 等 |
| `state.db` | SQLite 会话数据库（FTS5 全文检索） |
| `skills/` `memories/` `sessions/` `cron/` | 技能 / 记忆 / 网关路由 / 定时任务 |

开发用配置初始化（CONTRIBUTING.md:152-159，PowerShell 版）：

```powershell
$h = "$HOME\.hermes"
New-Item -ItemType Directory -Force "$h\cron","$h\sessions","$h\logs","$h\memories","$h\skills" | Out-Null
Copy-Item cli-config.yaml.example "$h\config.yaml"
if (-not (Test-Path "$h\.env")) { New-Item -ItemType File "$h\.env" }
Add-Content "$h\.env" "OPENROUTER_API_KEY=***"   # 至少配一个 LLM provider key
```

> **重要约束**（AGENTS.md:102-107）：`.env` **只放密钥**（API key / token / 密码）。所有"行为配置"——超时、阈值、功能开关、显示偏好——都进 `config.yaml`。不要新增 `HERMES_*` 环境变量来做非密钥配置，PR 会被拒。

## 3. 如何 Debug

### 3.1 第一站：`hermes doctor`

任何"装好了但跑不起来"的问题，先跑 `hermes doctor`（实现见 `hermes_cli/doctor.py`）。它会加载 `~/.hermes/.env`，检查 LLM provider key（`OPENROUTER_API_KEY` / `OPENAI_API_KEY` / `ANTHROPIC_API_KEY` 等一长串，doctor.py:32-55）、系统依赖、浏览器可运行性等，并按平台给出对应的安装命令（Windows 上给 `uv pip install` / `winget`，doctor.py:61-70）。

### 3.2 用 debugpy 挂调试器

`debugpy==1.8.20` 在 `dev` extra 里（pyproject.toml:157），这是 VS Code "attach to process" 用的 DAP 调试后端。

> **「待确认」**：仓库里**没有**内建的"自动启动 debugpy 监听端口"的开关——`Grep debugpy` 只在 `dev` 依赖声明、以及 `software-development/python-debugpy` 技能文档里出现，核心代码不主动 `debugpy.listen()`。所以挂调试器需要你**手动注入**。常见两种方式：

**方式一：在你想断点的代码里临时插入监听**（最简单，调长生命周期进程如 gateway 时好用）：

```python
import debugpy
debugpy.listen(("127.0.0.1", 5678))
print("debugpy listening on 5678, waiting for client...", flush=True)
debugpy.wait_for_client()   # 阻塞直到 VS Code attach
```

然后在 VS Code 用 "Python: Attach" 连 `127.0.0.1:5678`。

**方式二：从命令行用 debugpy 启动 CLI**：

```powershell
.\.venv\Scripts\python.exe -m debugpy --listen 5678 --wait-for-client -m hermes_cli.main chat -q "Hello"
```

（仓库内的 `software-development/python-debugpy` 技能文档对 pdb / debugpy / DAP 远程附加有完整 recipe，可作参考。）

### 3.3 打开 debug 日志开关

代码里有**分模块的 DEBUG 环境变量开关**，不是一个统一的 `HERMES_DEBUG`。逐个列举（来自 `Grep DEBUG`）：

| 环境变量 | 作用 | 代码位置 |
| --- | --- | --- |
| `HERMES_LOG_LEVEL` | 调整日志级别（如 `INFO` / `DEBUG`），让更多细节写进日志文件 | hermes_cli/auth.py:2473 |
| `HERMES_PLUGINS_DEBUG=1` | 插件发现过程的详细日志，输出到 stderr + `agent.log` | hermes_cli/plugins.py:78-115 |
| `HERMES_DEBUG_INTERRUPT` | 记录中断（interrupt）的 set/check 调用 | tools/interrupt.py:24-54 |
| `HERMES_VOICE_DEBUG=1` | 语音链路 debug 面包屑 | hermes_cli/voice.py:227-239 |
| `WEB_TOOLS_DEBUG=true` | web_search/web_extract 详细日志，存 JSON 到 `logs/` | tools/web_tools.py:335 |
| `VISION_TOOLS_DEBUG=true` | 视觉工具 debug 会话 | tools/vision_tools.py:48 |
| `MOA_TOOLS_DEBUG=true` | mixture-of-agents 工具 debug | tools/mixture_of_agents_tool.py:86 |
| `HERMES_LANGFUSE_DEBUG` | Langfuse observability 详细日志 | plugins/observability/langfuse |

这些工具级开关背后是统一的基础设施 `tools/debug_helpers.py` 的 `DebugSession` 类（debug_helpers.py:36-58）：构造时读 `env_var`，关闭时所有方法都是几乎零开销的空操作；开启时把每次工具调用记成 JSON 写到 `~/.hermes/logs/`。用法示例（debug_helpers.py:7-21）：

```python
from tools.debug_helpers import DebugSession
_debug = DebugSession("web_tools", env_var="WEB_TOOLS_DEBUG")
_debug.log_call("web_search", {"query": q, "results": len(r)})
_debug.save()
```

PowerShell 里临时开一个开关：

```powershell
$env:WEB_TOOLS_DEBUG = "true"; hermes chat -q "搜一下今天的新闻"
```

### 3.4 流式诊断（stream_diag）

当流式 chat-completions 请求在中途断掉，`agent/stream_diag.py` 会收集"为什么断"的诊断信息：哪个 Cloudflare 边缘节点、OpenRouter 下游用了哪个 provider、断前收到多少字节/chunk、HTTP 状态、底层 httpx 异常类。它同时写 `agent.log`（完整细节）和状态行（精简版）。要关注的响应头列表见 stream_diag.py:27-38（`cf-ray`、`x-openrouter-provider` 等）。排查"模型回到一半断流"时，去 `agent.log` 搜这些字段。

### 3.5 日志系统 —— 怎么看日志

集中式配置在 `hermes_logging.py`，单一入口 `setup_logging()`，CLI 和 gateway 启动早期都会调（hermes_logging.py:1-27）。生成的文件都在 `~/.hermes/logs/`：

| 文件 | 内容 |
| --- | --- |
| `agent.log` | INFO+，所有 agent/工具/会话活动（**主日志，兜底**） |
| `errors.log` | WARNING+，只有错误和警告（**快速排查首选**） |
| `gateway.log` | gateway 专属事件（`mode="gateway"` 时） |
| `gui.log` | dashboard / websocket / TUI-gateway 事件 |

每条日志带 `[session_id]` 标签（`set_session_context()` 注入，hermes_logging.py:23-26），可按会话过滤关联。所有 handler 用 `RedactingFormatter`，**密钥永远不会落盘**。

PowerShell 实时看日志：

```powershell
Get-Content "$HOME\.hermes\logs\agent.log" -Wait -Tail 50    # 类似 tail -f
Get-Content "$HOME\.hermes\logs\errors.log" -Tail 30         # 只看错误
```

> **Windows 日志轮转的坑**（hermes_logging.py:37-58，必读）：stdlib 的 `RotatingFileHandler.doRollover()` 用 `os.rename()`，当**另一个进程**以追加模式持有 `agent.log` 句柄时会抛 `PermissionError [WinError 32]`——而 Hermes 里这几乎是常态（TUI、gateway、`hy_memory` 服务、MCP server、按需 CLI 命令都从独立进程写日志）。结果是 `agent.log` 卡在 5 MiB 阈值、每次 emit 都往 stderr 刷回溯。解决方案：**仅在 Windows** 把 `RotatingFileHandler` 别名为 `concurrent-log-handler` 的 `ConcurrentRotatingFileHandler`（用 `portalocker`/pywin32 做跨进程文件锁），POSIX 上保持 stdlib 不变（因为 POSIX rename 打开的文件没问题）。参见 issue #44873。

另外 `hermes_logging._safe_stderr()`（hermes_logging.py:79-90）把 stderr 包成 `errors='replace'`，避免 Windows 旧版控制台编码（cp1252/cp949）遇到 em-dash 等字符时 `UnicodeEncodeError` 崩进程。

### 3.6 `hermes debug share`

要把环境信息 + 日志发给别人求助，用 `hermes debug share`（hermes_cli/debug.py）。它**默认在上传前对日志脱敏**（`redact_sensitive_text(force=True)`），把 `logs/*.log` 里的凭据擦掉再传到 paste 服务（paste.rs，回退 dpaste.com），返回一个 6 小时后自动删除的 URL（debug.py:1-57）。子命令选项（subcommands/debug.py:25-30）：`--lines 500`（更多日志行）、`--expire 30`（保留天数）、`--local`（只本地打印不上传）、`--no-redact`（关闭脱敏，慎用）。

## 4. 测试体系

### 4.1 tests/ 目录结构

按子系统分目录（`tests/<subsystem>/`）：

```
tests/
├── agent/        run_agent / AIAgent 相关
├── cli/          交互式 CLI 行为
├── hermes_cli/   CLI 命令实现
├── gateway/      消息网关
├── cron/         定时任务
├── tools/        各工具（terminal/browser/mcp/file_sync…，数量最多）
├── acp / acp_adapter   ACP 适配器
├── providers / run_agent / hermes_state
├── plugins / honcho_plugin / openviking_plugin / tui_gateway
├── e2e/          端到端真实路径
├── integration/  需要外部服务（API key / Modal / Daytona）—— 默认跳过
├── stress/       压力测试
├── fakes/        测试替身（如 fake_ha_server.py）
└── fixtures/ conftest.py / _isolate_plugin.py
```

### 4.2 跑测试：`scripts/run_tests.sh`（务必用它）

**铁律**（AGENTS.md:1252）：**永远用 `scripts/run_tests.sh`，不要直接调 `pytest`。** 因为脚本强制了与 CI 一致的"洁净环境"，否则一台 16+ 核、设了 API key 的开发机会和 CI 产生分歧，多次造成"本地过 CI 挂"或反过来的事故。

这是 **bash 脚本**，Windows 上要用项目自带的 Git Bash 跑（`%LOCALAPPDATA%\hermes\git`）。脚本做的事（run_tests.sh:1-27）：

- 通过 `scripts/run_tests_parallel.py` 做**每文件隔离**——每个测试文件在自己新生成的 `python -m pytest <file>` 子进程里跑，杜绝模块级状态泄漏。
- 强制 `TZ=UTC`、`LANG=C.UTF-8`、`PYTHONHASHSEED=0`（确定性）。
- 用 `env -i` 清空环境再 opt-in，**任何凭据变量都不会泄露**进测试（run_tests.sh:62-80）。
- 自动探测 venv：先 `.venv`，再 `venv`，再 `~/.hermes/hermes-agent/venv`（run_tests.sh:37-42）。

用法（run_tests.sh:16-27 / AGENTS.md:1259-1263）：

```bash
scripts/run_tests.sh                                  # 全量，CI 对齐
scripts/run_tests.sh tests/gateway/                   # 单个目录
scripts/run_tests.sh tests/agent/test_foo.py          # 单个文件
scripts/run_tests.sh tests/agent/test_foo.py::test_x  # 单个用例
scripts/run_tests.sh -j 4                             # 限制并行度
scripts/run_tests.sh -- -v --tb=long                  # `--` 之后透传给 pytest
scripts/run_tests.sh --no-isolate tests/foo/          # 关闭子进程隔离（调试时更快）
```

> **文档内的小不一致「待确认」**：`run_tests.sh` 实际走的是 `run_tests_parallel.py`（每文件子进程），而 AGENTS.md:1252-1297 的描述提到 `-n auto` xdist + `tests/_isolate_plugin.py` 每用例隔离。两者目标一致（隔离 + CI 对齐），但实现细节表述有出入，以你机器上脚本的实际行为为准。

### 4.3 不用 wrapper 时（IDE 直接跑 pytest）

如果 IDE 必须直接 shell `pytest`，至少先激活 venv。隔离插件会从 `pyproject.toml` 的 `addopts` 自动加载，所以仍有每用例进程隔离（AGENTS.md:1303-1313）。`tests/conftest.py` 也用 autouse fixture 兜底了"清凭据 / 临时 HOME / UTC / C.UTF-8"，所以任何 pytest 调用（含 IDE）都拿到洁净环境（AGENTS.md:1299-1301）。

```powershell
.\.venv\Scripts\Activate.ps1
python -m pytest tests\ -q
python -m pytest tests\agent\test_foo.py -q --no-isolate   # 调试单测、要快
```

### 4.4 pytest 配置（pyproject.toml）

`[tool.pytest.ini_options]`（pyproject.toml:348-355）：

- `testpaths = ["tests"]`
- `markers`：
  - `integration` —— 标记需要外部服务（API key、Modal 等）的测试；
  - `real_concurrent_gate` —— 退出某个 autouse stub。
- `addopts = "-m 'not integration'"` —— **默认就跳过 integration 测试**，因为它们在普通 CI 太慢。要专门跑：`scripts/run_tests.sh -- -m integration`。

异步测试用 `pytest-asyncio==1.3.0`（pyproject.toml:157），所以可以直接写 `async def test_...`。

### 4.5 测试理念（AGENTS.md，写测试前必读）

- **行为契约 > 快照（Behavior contracts over snapshots）**（AGENTS.md:80-83、1323-1370）：测试要断言"两份数据**之间的关系/不变量**"，而不是冻结某个当前值。反例叫 **change-detector test**——每次模型目录更新、配置版本号 +1、枚举数量变化就挂，纯属浪费工程时间。
  - 不要写：`assert "gemini-2.5-pro" in _PROVIDER_MODELS["gemini"]`、`assert DEFAULT_CONFIG["_config_version"] == 21`、`assert len(...) == 8`。
  - 要写：`assert "gemini" in _PROVIDER_MODELS`、`assert raw["_config_version"] == DEFAULT_CONFIG["_config_version"]`、"目录里每个模型都有 context-length 条目"这类不变量。
  - 判断法则：**像当前数据快照的就删，像两份数据必须满足的契约的就留**。
- **E2E 真实路径 > 全绿的 mock 单测**（AGENTS.md:84-87）：凡是碰到解析链、配置传播、安全边界、远程后端、文件/网络 I/O 的，要用**真实 import** 跑**真实路径**（针对临时 `HERMES_HOME`），别用 mock —— mock 会藏住集成 bug。dead code 没有 E2E 证明不许接进活路径（AGENTS.md:1227-1230）。
- **临时 HOME 的坑**（AGENTS.md:1166、1235）：mock `Path.home()` 的测试**也要**设 `HERMES_HOME`，否则代码走的是 `HERMES_HOME` 而非 `home()`。

### 4.6 跨平台测试（Windows 相关）

POSIX-only 的系统调用需要 skip 标记（CONTRIBUTING.md:822-835）：

```python
@pytest.mark.skipif(sys.platform == "win32", reason="symlink/POSIX-only")
```

常见需要跳过的：符号链接、`0o600` 文件模式、`signal.SIGALRM`、`os.setsid`/`os.fork`；Windows 专属回归测试反过来用 `skipif(sys.platform != "win32", ...)`。若 monkeypatch `sys.platform`，记得同时 patch `platform.system()` / `platform.release()` / `platform.mac_ver()`，否则半补丁的测试在 Windows runner 上仍走错分支。

## 5. 代码质量工具

### 5.1 ruff（只开一条规则）

`[tool.ruff]`（pyproject.toml:364-383）的配置非常特殊：**几乎所有 lint 都关了，只开 `PLW1514`（unspecified-encoding）**。原因（pyproject.toml:367-375）：裸 `open()` / `read_text()` / `write_text()` 在文本模式下默认用系统 locale 编码，**Windows 上（US locale）是 cp1252**，会静默损坏任何非 ASCII 文件内容——他们在一次调试里连踩三个 Windows 沙箱回归才加了这条强制规则。需要 `preview = true` 因为 PLW1514 是 preview 规则。`tests/`、`skills/`、`plugins/` 等目录豁免（pyproject.toml:377-383）。

所以**写文件时一定要显式指定编码**：

```python
path.read_text(encoding="utf-8")
open(path, "w", encoding="utf-8")
```

跑 ruff：

```powershell
.\.venv\Scripts\ruff.exe check .
```

### 5.2 ty（类型检查）

`ty==0.0.21`（Astral 的类型检查器）在 dev extra 里。配置 `[tool.ty]`（pyproject.toml:357-362）：`python-version = "3.13"`、`unknown-argument = "warn"`、`redundant-cast = "ignore"`。

```powershell
.\.venv\Scripts\ty.exe check .
```

### 5.3 scripts/ 目录里有用的脚本

### 6.2 示例思路：如何 debug 一个工具调用

假设你怀疑 `web_search` 工具行为异常，排查路径：

1. **先看现象**：`Get-Content $HOME\.hermes\logs\errors.log -Tail 30` 看有没有报错；再翻 `agent.log` 找对应 `[session_id]`。
2. **开工具级 debug 开关**：`$env:WEB_TOOLS_DEBUG = "true"`，再复现一次。`DebugSession` 会把每次调用（query、结果数等）写成 JSON 到 `~/.hermes/logs/`（debug_helpers.py:36-58）。
3. **挂调试器看实参/控制流**：在 `tools/web_tools.py` 里要断的位置插入 §3.2 的 `debugpy.listen` 三行，或用 `python -m debugpy --listen 5678 --wait-for-client -m hermes_cli.main chat -q "..."`，VS Code attach 到 5678，在工具 handler 上下断点。
4. **若是流式中断**：去 `agent/stream_diag.py` 关注的响应头（`x-openrouter-provider` 等）在 `agent.log` 里找断流原因。
5. **写一个行为契约测试固化修复**：放到 `tests/tools/`，断言"输入 → 输出关系"的不变量（不是某个具体返回值），用真实 import 跑真实路径（AGENTS.md:80-87）。涉及外部 API 的标 `@pytest.mark.integration`（默认会被跳过）。
6. **提交前自检**：`ruff check .`、`ty check .`、`python scripts\check-windows-footguns.py --diff main`，再用 Git Bash 跑 `scripts/run_tests.sh tests/tools/`。
