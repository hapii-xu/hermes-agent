# 06 · 学习计划与路线图

> **本章导读**：把"读这个项目"变成一条有节奏、可执行的路径。下面给出**分阶段学习计划**、**每阶段的目标 / 动手任务 / 验收标准**，以及一些**通用的读码技巧**。你可以按自己的节奏走，但建议顺序不要跳。

---

## 0. 学前准备（约 0.5 天）

**目标**：把项目跑起来，建立"能动手"的环境。

- [ ] 通读 `README.md` 与本目录 `01-项目总览.md`，建立全局心智模型。
- [ ] 按 `05-开发调试与测试.md` 搭好 uv 环境，成功执行 `hermes doctor`。
- [ ] 跑通一次最小对话：`hermes`，配置一个模型（`hermes model`），随便聊一句。
- [ ] 浏览 `AGENTS.md` 的前两章（"What Hermes Is" + "Contribution Rubric"），重点记住两条铁律：**提示缓存神圣** + **窄腰设计**。

**验收**：能在本地启动 CLI 并完成一轮真实对话；能说出两条设计铁律是什么、为什么。

---

## 阶段一 · 看懂"骨架"：启动与架构（约 1–2 天）

**对应文档**：`02-架构与启动流程.md`

**目标**：搞清 `hermes` 敲下去之后，控制流如何从 `hermes_cli/main.py` 一路走到 agent 核心。

**动手任务**：
1. 从 `hermes_cli/main.py:main` 开始，用编辑器"跳转定义"顺着读，画出你自己的启动调用图（对照文档里的流程图校正）。
2. 在启动链路上挑 1–2 个函数，打日志或断点（见 `05` 的 debug 方法），实际跑一遍观察执行顺序。
3. 列出根目录每个"god file"的职责（对照 `01` 的速查表，自己补充）。

**验收**：能口述 `hermes` → CLI 解析 → bootstrap → agent 启动的主链路；能指出 `config.yaml` 与 `.env` 各自管什么。

---

## 阶段二 · 看懂"心脏"：Agent 循环与工具系统（约 3–4 天，重点）

**对应文档**：`03-核心Agent循环与工具系统.md`

**目标**：理解一个 turn 的完整生命周期，以及工具是如何定义、注册、执行的。这是整个项目最值得花时间的部分。

**动手任务**：
1. 精读 `agent/conversation_loop.py`，在"构建 prompt → 调模型 → 解析 tool call → 执行工具 → 回灌结果"每个阶段打断点，跑一次带工具调用的对话（比如让 agent 读一个文件），逐步观察。
2. 跟读一个具体工具从声明（`model_tools.py` / `toolsets.py`）到执行（`tools/` 下对应实现，经 `agent/tool_executor.py`）的全过程。推荐挑 `tools/file_tools.py` 这种简单的。
3. 读 `agent/prompt_caching.py` + `agent/system_prompt.py`，理解"为什么系统提示必须 byte-stable"，并在代码里找出**一个**为保护缓存而做的具体约束。
4. 读 `agent/context_engine.py` / `context_compressor.py`，理解长对话如何压缩。

**验收**：能画出 turn 生命周期图；能解释新增一个工具要动哪些文件；能说清提示缓存为什么神圣、压缩为什么是唯一例外。

---

## 阶段三 · 看懂"灵魂"：自我改进闭环（约 2–3 天）

**对应文档**：`04-核心特色功能.md`（学习闭环部分）

**目标**：理解 Hermes 区别于普通 agent 的核心——记忆 + 技能 + curator 的闭环。

**动手任务**：
1. 读 `agent/memory_manager.py` + `agent/curator.py`，找出"周期性 nudge 自己持久化知识"的触发点。
2. 打开 `skills/` 下任意一个技能，读它的 `SKILL.md`，理解技能格式（兼容 agentskills.io）。然后读 `agent/skill_commands.py` / `skill_preprocessing.py`，理解技能如何被加载进上下文。
3. 读 `agent/learn_prompt.py`，理解"复杂任务后自动造技能"的逻辑。
4. （可选）实际让 agent 完成一个稍复杂的任务，观察它是否生成/更新了技能或记忆。

**验收**：能讲清"记忆—技能—curator"三者如何构成闭环；能说出一个技能文件的最小结构。

---

## 阶段四 · 看懂"触角"：网关 / cron / 插件（约 2 天）

**对应文档**：`04-核心特色功能.md`（网关 / cron / 插件部分）

**目标**：理解 Hermes 如何"活在你常用的地方"以及如何被扩展。

**动手任务**：
1. 读 `gateway/run.py` + `gateway/platform_registry.py` + `gateway/platforms/` 下一个平台适配器（如 telegram），理解单进程多平台模型。
2. 读 `cron/` 与 `tools/cronjob_tools.py`，理解定时任务如何被调度与投递。
3. 挑 `plugins/` 下一个插件（如某个 memory 后端），看它的 `plugin.yaml` 与代码，理解插件接入约定。

**验收**：能解释一条消息从某平台进来、到 agent 处理、再回复出去的路径；能说出"加一个新平台/新记忆后端"大致要做什么。

---

## 阶段五 · 融会贯通：改一处、测一处（约 2–3 天）

**对应文档**：`05-开发调试与测试.md`

**目标**：从"读"过渡到"改"，用一个小改动跑通完整的开发—测试闭环。

**动手任务（任选其一）**：
- 给某个现有工具加一个小参数 / 小行为，并补一个**行为契约测试**（参考 `tests/agent/` 风格，不要写快照测试）。
- 修一个你在 issue 列表里能复现的小 bug（按 `AGENTS.md` 的"好的修复"标准：复现 → 定位到具体行 → 修整个 bug 类）。
- 写一个最小的自定义 skill 放进 `skills/`，让 agent 能调用它。

**验收**：`scripts/run_tests.sh` 跑过相关测试；改动符合两条铁律（不破坏缓存、不无谓地往核心塞东西）；能讲清你改了什么、为什么。

## 通用读码技巧

1. **善用项目自带文档**：`AGENTS.md` 和 `CONTRIBUTING.md` 是"为什么这么设计"的一手资料，很多反直觉代码都有注释解释原因（尤其是 Windows 兼容、供应链、缓存相关）。遇到"这代码怎么这么绕"先搜注释。
2. **从入口顺着读，别从中间切入**：大文件（cli.py 700KB）不要试图通读，用"跳转定义 / Grep 找函数"按调用链读。
3. **善用 Grep 找定义**：`def main`、`class Xxx`、工具名等。
4. **跑起来 + 打断点胜过空读**：在关键函数加日志/断点，用真实对话驱动一次，执行顺序立刻清晰（见 `05`）。
5. **读测试理解契约**：`tests/` 下的测试是"这段代码到底承诺了什么"的最佳说明书。
6. **注意两条铁律的"投影"**：看到任何"重建 prompt / 换工具集 / 注入用户消息"的代码，先问"这会不会破坏缓存"——项目里大量防御代码都是为它服务的。
