两条贯穿全局的设计铁律（先记住）

理解这两条，才能读懂代码里大量看似"绕"的设计。出处：AGENTS.md 开头。

①

逐对话的提示缓存是神圣的

系统提示在整个对话生命周期内必须逐字节稳定（byte-stable），否则缓存失效、成本暴涨。唯一例外是上下文压缩。

②

核心是"窄腰"，能力长在边缘

每个核心工具都会出现在每次 API 调用里，所以新增核心工具是最后手段。优先在边缘扩张。

足迹阶梯（Footprint Ladder）

新增能力时，选最高（足迹最小）且能正确解决问题的那一级。出处：AGENTS.md:171-196。

  1. 1
    扩展已有代码能力只是现有东西的变体，零新增足迹。
  2. 2
    CLI 命令 + skill可用 shell 命令表达的配置/状态/基建管理；零 model-tool 足迹。
  3. 3
    Service-gated 工具（check_fn）需结构化参数/返回，仅当前置条件满足时出现；否则零足迹。
  4. 4
    Plugin第三方/小众/用户特定能力，住在 ~/.hermes/plugins/，运行时发现。
  5. 5
    MCP server（进 catalog）确实需要是工具但非内核基础，零永久 core-schema 足迹。
  6. 6
    新 core tool（最后手段）能力基础性、几乎所有用户都需要、terminal+file 无法触达——才考虑。
